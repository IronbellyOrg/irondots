# Profile-owner-authored communication adapter

Adapter **1.0.0**, instruction-level route. Applies only when the requested output is a message, reply, comment or notification explicitly written as the profile owner. Dot summaries, AI-created domain reports, task-field data and quotations retain their actual authorship. This adds no sending, data-sharing or AI communication authority and changes none of the existing execution/reporting schemas.

The public `write-as-ryan` package is a generic template, not a personal profile. Configure a separately authorized private profile before claiming profile-based readiness; synthetic examples are never production evidence.

## Prepare and delegate

1. Read the actual registered `write-as-ryan` entrypoint, its workflow safeguards, current manifest and exact profile resource, plus generic writing-style and the relevant channel rules. Record actual current reads. On resume or a new writer, reread rather than trusting a prior version label. If the route is absent/stale or the profile cannot be verified, hold the affected publication and show a clearly provisional private draft when useful. Follow the writing skill's informed exact-draft exception procedure; never waive safety/permission gates.
2. Preserve the existing ClickUp AI-first route. Hydrate known continuity locally before provider calls. AI remains executor of the authorized ClickUp batch and creator of substantive ClickUp work. The coordinator may prepare private staging/validation but cannot substitute native domain writes or independently rewrite substantive AI reports. Do not recursively invoke this ClickUp router from the style layer.
3. Carry only relevant privacy-safe wording constraints and authorized facts in the already-authorized AI request. Keep raw correspondence samples, private profile/provenance, full receipts and internal paths local. A permission to draft is not permission to contact AI or share extra data. Include actual literal wording, audience, no-additions constraints and the requirement to return proposed final text without publishing it when text is not yet validated. A profile version label does not prove Brain can load this private skill.

## Validate before publication

4. For newly composed Profile-owner-authored wording, obtain AI's exact proposed text before publication, then run the writing skill's current-guide and exact-draft checks locally (or its documented manual equivalent). Return material mismatches to the authorized AI route for correction, or obtain the profile owner's informed exception for that exact text. Do not silently rewrite AI's substantive output and represent it as AI-created.
5. After the exact text passes, preserve those bytes in the separately eligible execution payload and require no rewrite. Recheck current recipient, scope, authority, dependencies and any new replies. Any text, audience, scope or context change requires the affected validation/approval review again. Retain the compact private result with the operation's exact payload hash and evidence. Existing execution helper contracts remain unchanged and do not themselves consume this style receipt.
6. If supported AI execution cannot separate composition from publication or preserve the validated text, the exact prepublication gate is not established: hold that affected publication and report the capability gap. Do not claim that checking after publication satisfied this gate. Do not add unauthorized provider calls; if staging needs new communication authority, ask for that bounded action.
7. Reconcile uncertain sends/effects through the existing continuity/verification route before any retry. A style failure never authorizes a duplicate send, native fallback, quota bypass or a change to the audience. Read back the actual effect when authorized and compare returned text to the validated payload; accepted is not delivered/read.

This adapter and the local writing helper are not a connector interceptor. Instructions can be missed by a caller; managed email/Slack/texting entrypoints are not modified. Report observed route coverage, missing helper/read access and actual provider evidence separately. Offline fixtures do not establish live AI execution.
