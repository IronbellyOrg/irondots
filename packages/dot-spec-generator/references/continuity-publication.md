# Continuity and publication

Load for reconciliation, interrupted runs or authorized publication. Inputs: current artifact, accepted decisions, source versions, known effects and exact write authority. Output: preserved/reconciled candidate, safe publication receipt or precise pending state.

For one supplied correction, prefer a compact amendment: exact changed section/phrase, replacement/addition, source/reason, observable check and unresolved gate. Reuse existing requirement IDs rather than create a duplicate miniature specification unless new behavior actually needs a new requirement. Do not repeat the same obligation in edit prose, a new table and a threat narrative. Keep all material constraints. Loading full research guidance merely because two supplied documents are compared is unnecessary unless new material research, a conflict or dependency analysis requires it.

Before changing a statement, identify whether it governs planning/decision truth, runtime artifact storage or cache behavior. Preserve unaffected categories and existing canonical work. A native-first artifact preference does not negate ClickUp's planning-source-of-truth role.

Read existing human content and comments as evidence. An older comment does not automatically override a later human edit. Resolve authority, chronology and scope; material conflict pauses only the affected write. Preserve stable requirement keys and orphan stories. Uncovered requirements produce proposals before any authorized shell creation. Never delete merely because a story appears stale.

Keep a checkpoint: run/operation identity, actual request and latest corrections, source versions, decisions, selected modules, candidate/diff, completed/uncertain effects, exact blocker and next permitted step. Repeated voice transcripts do not create duplicate tasks. Cancellation or reduced scope supersedes old replies.

## Shared reporting protocol

The generator's own reporting and every newly authored skill specification must use [the ClickUp-owned reporting protocol](https://github.com/IronbellyOrg/irondots/blob/main/packages/clickup/references/reporting-protocol-v1.md), `dot-reporting/1.0`, without an independently designed alternative. Load that resource for local progress, completion reporting or specifying a skill's reporting contract. Discover/read the registered `clickup` skill entrypoint, protocol, and exact `dot-reporting-request/1.0` and `dot-reporting-result/1.0` templates at its `assets/reporting-request.md` and `assets/reporting-result.md`. Use its reporting preparation/receipt-normalization route; it does not publish or send Brain messages. Use the fixed sequence and define only its scoped parameters. Block affected readiness for missing access, unsupported versions, malformed packets or unverified transport; never invent capability or interpret a partial receipt as full publication. The template requires the protocol version, exact source/runtime read route, access evidence or gap, and observable acceptance; merely linking a resource does not grant future access.

No initial ClickUp task is required and no ongoing report writes are permitted. Work local-first under the authorized `output/` location. Preserve the existing canonical record; the final authorized batch is caller-owned. A justified no-op/not-applicable route is defined by the same protocol, not a custom workflow. Missing protocol assessment blocks a new skill specification from being called ready for review. This reporting protocol is separate from the unchanged read/propose-only Brain delegation contract.

## Safe publication and recovery

Before publication identify payload, destination/audience and known notification/automation effects. A status transition or comment can trigger effects. Prefer provider revision/conditional update. Otherwise scoped append/narrow patch, retained baseline/diff, immediate pre-write reread, stop on relevant drift, then readback. Readback is not atomicity. If only whole-body replacement of human-edited content is possible without concurrency protection, prepare a reviewable patch rather than automatically overwrite.

Unknown consequential downstream effects or broader sensitive-data access blocks publication. Do not broaden permissions or create a list merely to fit a template. One writer owns canonical work: IronFlow human-work records for AI/automation, CEO for other personal work, explicit project/privacy destinations otherwise.

Outcome verification and canonical writeback are independent. A verified result with failed logging remains verified with pending writeback; only the logging operation resumes. Uncertain writes require authoritative readback before retry. A timeout is not proof nothing happened.

Quota/access denial is a real dependency. Record provider retry guidance, make no disallowed live calls, and do not evade it through credentials/account/transport. Independent local work can continue; current source/access must be rechecked after recovery.

Keep skill resources native-persistent if supported. External ClickUp/Git fallback uses one canonical authority, exact source/version/hash, access and drift policy; derived caches are not second editable truth. Raw replies and source dumps do not belong in durable personal memory. Keep only necessary, permitted run artifacts and ask the coordinating assistant to save durable preferences/facts.
