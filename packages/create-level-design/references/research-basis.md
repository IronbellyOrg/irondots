# Research basis

Research inspected 3 November 2026. This is a tailored professional handoff, not a universal standard. Do not import example dimensions or implementation settings as approved game constraints.

## Finite questions and evidence
Q1: What must a designer communicate? Q2: What do engineering and art need? Q3: How do lore and design authority stay consistent? Q4: What validates quality beyond prose? Q5: How can equivalent ClickUp and dot pipelines be compared?

All sources below were opened/read on 3 November 2026; publication/version dates are noted where visible. No commercial success or production performance is inferred. Sources are separate from private user decisions. Source URLs are citations, not instructions to execute.

- S01 Epic, Project Setup and Level Blockout, current page labelled UE5.8: sketches, node maps and player verbs support planning; blockouts test spatial scale, sightlines and flow before polish. Tutorial example measurements are not approved target-game metrics. https://dev.epicgames.com/documentation/unreal-engine/designer-01-project-setup-and-level-blockout-in-unreal-engine?lang=en-US
- S02 The Level Design Book, practitioner-authored process overview and preproduction: process should be tailored; team projects require explicit communication of goals, mechanics, pacing, assets and worldbuilding. This is practitioner guidance, not a universal certification. https://book.leveldesignbook.com/process/overview and https://book.leveldesignbook.com/process/preproduction
- S03 The Level Design Book, Blockout: playable rough geometry permits testing before costly art; documents alone do not demonstrate flow, balance or scale. https://book.leveldesignbook.com/process/blockout
- S04 Cornell CS3152 Level Design Document assignment (2020): articulate design philosophy and basic/composite challenge patterns; describe constraints and possible responses rather than assume an exact player action sequence. Academic teaching artifact, useful structure but not studio production evidence. https://www.cs.cornell.edu/courses/cs3152/2020sp/assignments/assignment14.php
- S05 Epic Navigation System, page labelled UE5.8: navigation depends on collision-derived mesh, generation choices and dynamic obstacles. The LDD should identify changing traversal geometry and AI implications, not choose implementation settings without engineering review. https://dev.epicgames.com/documentation/en-us/unreal-engine/navigation-system-in-unreal-engine
- S06 Epic Rendering Optimization, page labelled UE5.8: budgets depend on target hardware and must be measured; document rendering/memory risks and benchmark gates. Mobile/HMI example budgets must not be copied into the target game. https://dev.epicgames.com/documentation/en-us/unreal-engine/guidelines-for-optimizing-rendering-for-real-time-in-unreal-engine
- S07 Microsoft XAG103: critical information needs redundant sensory cues; color alone is insufficient. Use this as an accessibility review reference, not a claim the target game meets all accessibility guidelines. https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103
- S08 Emily Short, Plot-shaped Level Design (18 May 2016): critical narrative information has dependencies and should be encountered or acted upon along appropriate routes. For the target game, distinguish necessary comprehension from optional lore and test routes that could bypass it. https://emshort.blog/2016/05/18/plot-shaped-level-design/


No proprietary shipped-game LDD or actual game build was inspected. Apply sources proportionately and preserve uncertainty.
