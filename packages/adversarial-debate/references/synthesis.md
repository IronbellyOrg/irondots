# Requested draft synthesis

Load only when the actual request includes a merged draft. Inputs: authorized output, selected base or explicit no-base strategy, evidence and accepted-scope change plan. Output: new draft, provenance, validation and unresolved issues. No canonical overwrite, sending or execution is implied.

For each proposed change record source variant/section, target section, operation, rationale tied to an issue, risk and affected constraints. Record useful rejected alternatives. A requested local draft needs no redundant approval ritual, but material user decisions and consequential approvals cannot be inferred. Preserve later restrictions and stop new work on cancellation.

Create a separate fresh no-history synthesis writer under [isolation](isolation.md). Supply the original packet first, then disclose the authorized current-run selection and change plan in a labeled synthesis stage. Prior-run results remain withheld until verdict lock, and the writer does not adjudicate its own work. A synthesis writer follows the plan, preserves original files and sources, and reports any unplanned change needed instead of improvising authority. Attribute meaningful sections/blocks through a sidecar or suitable annotations. Keep private authorship mappings out of blinded recipient output. A failed merge retains the plan and recoverable partial work.

Validate requirements, critical claims, references, structure, existing contradictions and new contradictions. Distinguish baseline defects from regressions. A structurally sound draft is not domain-certified or ready for deployment. Unresolved critical findings keep the output qualified/partial. Return actual artifact identities and access states, not guessed URLs or fabricated file paths.
