# Isolation and staged disclosure

Read before any role dispatch. This protocol prevents deliberate history sharing and records observed exposure; it does not sandbox tools, files, memory, connectors or agents. A fresh agent can still have broad access. Never claim inaccessible material, complete auditing, causal independence or a controlled comparison without evidence of the corresponding enforcement. The record validator checks declarations, not that evidence's truth.

## Custodian and clean decision roles

The current parent may know earlier outcomes. Restrict it to authorized intake, neutral source packaging, dispatch transport, checkpoint storage and final publication. It must not advocate, prepare an outcome-led issue ledger, adjudicate, choose evidence to favor an earlier verdict, or relay its own evaluative summaries into the clean run. Create a **new coordinator/adjudicator** using native delegation with `fork_turns: "none"`; do the same for every advocate, required reviewer, generator and synthesis writer. Do not reuse a role from a prior run, inherit the parent transcript, or replace real workers with headings. Record dispatch arguments, resulting identities and actual receipts. If the tool cannot verify no inherited history, record `history_state: unverified` and the limitation. If no fresh worker can be created, return partial/blocked without simulating it.

The coordinator builds its issue ledger from the frozen original packet. Each advocate initially receives only that packet plus a neutral assigned perspective. The reviewer first receives original evidence, constraints and candidate artifacts, with no current advocacy, emerging consensus or earlier findings. Its independent assessment must be retained before challenge material is disclosed. A reviewer must not have generated or advocated the reviewed candidate. Generators receive only the authorized original brief; their new outputs become candidate source snapshots before separate comparison roles are dispatched. Identify them as same-run generated candidates, not independent external corroboration.

## Freeze the source packet

Use a new run ID and, when local output is authorized, a fresh output directory. A durable saved message or artifact receipt can substitute where no local write is available; do not create files solely for ceremony. Preserve original bytes, revisions and read coverage; use stable neutral candidate IDs. Include the user's actual decision question, constraints, frozen criteria, permitted source set and relevant authorization, plus the original artifacts and necessary method instructions. Quote only task-relevant instructions, not surrounding conversation that reveals earlier evaluations. Document supplied order and any masking transformation.

Exclude previous recommendations, scores, rankings, debate transcripts, referee critiques, synthesized summaries, private notes, prior-run file paths and outcome-revealing names or metadata. Do not merely hide author labels around prior analysis. Do not include a precomputed evaluative issue ledger or preferred answer. Maintain a manifest of every included source and its hash or dated immutable snapshot. Hash the exact packet bytes and retain the actual dispatch text or a faithful artifact of it. Give all advocates equal source/criteria content and coverage; assignment labels may differ. Do not overwrite originals to sanitize them.

If an artifact is itself a prior debate's derivative, label its lineage. It can be an authorized candidate but cannot be described as an original-source-only rerun of its ancestors. Obtain the original artifacts for that claim or report the limitation. A user criterion that mentions an earlier outcome must be represented faithfully; ask for clarification only when excluding it would change the task. Never quietly strip a binding constraint to manufacture a blind comparison.

## Stage current-run disclosure

1. **Initial:** Dispatch the clean coordinator, advocates and reviewer separately. Log packet IDs, recipients, dispatch/read evidence and actual history state. A successful spawn is not proof that all sources were read.
2. **Independent outputs:** Save each advocate's first statement and the reviewer's raw-source assessment with role identity, timestamp/sequence and receipt. Do not pass a sibling's output while another first statement is pending. The coordinator may receive outputs for collection but withholds adjudication until promised checks finish.
3. **Rebuttal:** For normal/deep runs, release the same completed prior-round packet to all advocates only after every expected advocate has completed that round. Keep no-response/capacity failures visible; do not shrink the roster. Quick has no rebuttal. A deep final round follows the same barrier.
4. **Reviewer challenge:** After its independent assessment is saved, provide only relevant **current-run** debate outputs, emerging candidate/consensus and traces. Record this separate disclosure and additions/changes to its findings. Do not replace its initial assessment. Check sufficiency and high-severity blockers before adjudication.
5. **Verdict lock:** After required rounds, checks and review, the coordinator emits the recommendation, conditions, dissent, source/criteria identities and limitations. Save exact bytes at a new non-overwritten location and record a SHA-256 digest, lock sequence and durable receipt outside the mutable result. A local file can be changed: a hash and write-once convention are tamper-evidence only, not access control. A saved message with exact verdict content and a stable receipt may substitute for a file. If no durable snapshot/receipt is available, withhold prior results and return the useful assessment as partial/blocked; do not claim the complete isolation protocol.
6. **Optional prior reveal:** Only after the lock receipt exists may the custodian release earlier results, if that comparison is in scope. Record reveal sequence and recipients. Put the comparison in a separate post-lock appendix. Never silently change the locked verdict. A later factual correction is a separately versioned addendum preserving both versions and exposure history; it is not a fresh blind judgment.

Record source, role and criteria changes. Material new evidence during a round requires a new equal packet and explicit invalidation/restart of affected independent work. Count every source read/disclosure in exposure equality, not only initial dispatch. Complete each stage only after its actual packet exposure and, for verified claims, its source/round read receipts. New original packets invalidate the affected role’s independent assessment and dependent rounds; new current-round packets invalidate that round’s outputs and later dependent rounds. Obtain renewed outputs before lock. Later reads/outputs cannot repair the eligibility frozen at lock. Do not silently give later speakers more evidence. Reversed-order checks use fresh roles and no earlier current-run judgments if called independent; a coordinator reread is only an order-sensitivity check and must be labeled as such. Neither establishes full debiasing.

## Access and read audit

Before dispatch, list allowed sources and known routes to excluded material: inherited history, shared filesystem, memory/search, sibling messages, reporting records and external connectors. Use supported restrictions only where actually available and authorized. Do not browse prior output to test whether a clean role can avoid it, and do not alter security settings without authority. Minimize exposed locators; prompt instructions are not access enforcement.

Retain actual source reads and disclosed packet receipts per role/stage, including unplanned accesses, omissions and uncertainty. Distinguish audit evidence available to the custodian from the role's self-report. `read_audit: complete` requires trustworthy coverage of all relevant reads, not a worker saying it complied or an absence of observed violations. `access_boundary: verified` requires evidence of enforced controls across relevant history, files, memory, connectors and messaging. Set `unverified`/`unavailable` when you cannot establish these facts.

Use `status: verified` and `claim: controlled_comparison` only with verified controls, complete audit, fresh no-history roles, original-only initial packets and correct disclosure ordering. Otherwise use `procedural_only`/`independent_attempt`, with the exact limits. Unknown history or missing audit is not evidence of contamination, but cannot establish control. Any actual excluded-result exposure before lock, inherited prior outcome, or contaminated initial packet yields `contaminated`; retain useful work as partial/blocked, stop calling it a clean comparison, and do not silently restart. A restart requires fresh run identity/roles/packets and authorization within the existing effort scope. A remembered outcome cannot be unlearned by telling the same agent to ignore it.

Keep these records outside the installed skill. Use [the isolation record](../assets/isolation-record.md) in new result/1.1 outputs. A legacy record can be summarized honestly, never backfilled with invented dispatch/read/lock evidence.
