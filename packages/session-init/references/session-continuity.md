# Continuity and reconnects

Resolve the existing approved-scope briefing and relevant task checkpoints, not all historical projects. Keep approved user decisions distinct from proposals and external statements. Current explicit corrections supersede stale preferences within applicable safeguards.

For each relevant operation retain owner, stage, completed effect IDs/receipts, uncertain effects, next permitted step and pending approvals. Resume the same operation. An uncertain send needs authoritative reconciliation before any retry; a failed report never replays the underlying action. Repeated transcript fragments are not repeated instructions. Do not restart a worker solely because a call reconnects.

A known call ID plus the same skill revision supports a refresh/no-op classification. A changed objective or explicit fresh initialization may prepare a new receipt without repeating effects. A missing call ID does not prove sameness or difference: use a new local invocation ID, link the prior receipt if available and state call relationship unknown. Do not derive call IDs from thread IDs. A new local invocation is not a new voice call.

Account for the complete approved working scope in the written briefing; keep only the minimum continuity in the compact prepared core. If context is missing, state the gap; continue independent conversation. Do not copy confidential runtime instructions, private memory infrastructure or unrelated personal details into user deliverables or external requests. A shared channel must not inherit private call content automatically.

On interruption, checkpoint the task owner, state and pending decision. At an actual call end or explicit user handback, return one concise handback when supported. Call end does not cancel previously authorized ongoing work. Do not claim a handback was spoken without evidence.

Reconcile decisions, closures and source freshness into the same existing briefing identity. Repeated invocation without material change avoids new artifact versions. A prior successful resource load is not proof that the current agenda, persistence or voice-delivery gates passed. Preserve old session-init/1.0 receipts as historical partial evidence; absent fields added in 1.1 remain unknown, never backfilled as success.
