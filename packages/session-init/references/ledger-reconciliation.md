# Manual session-init ledger reconciliation

Every explicit manual invocation, including a same-call refresh, attempts this once before preparing priorities. Answer conversations about Session Init without running it. Resume uncertain effects rather than replaying them. This is an instruction route, not a background job.

1. Recover the designated private to-do ledger, approved initiative/workspace scope, pending checkpoints and last verified mappings/baseline. Resolve exact local item ID ↔ verified workspace/list/task ID. Include every approved linked open item even if now closed in ClickUp, and known linked local closures pending remote confirmation. Partition other initiatives separately. Count the denominator, excluded and unmatched; never search/link by title or publish a private-only entry. A missing baseline is not new authority.
2. Discover and read actual ClickUp skill and its [ledger sync contract](https://github.com/IronbellyOrg/irondots/blob/main/packages/clickup/references/ledger-reconciliation-v0.1.md). Batch narrow reads through private approved ClickUp AI with only exact task IDs and needed fields. Independently verify material/provider claims under that contract, binding each observation to the unique current invocation and actual receipt from a read initiated for it; never relabel cached data; lack of access, timeout, rate limit, stale snapshot, missing field or pagination is partial, not unchanged. Resolve precise per-list status mappings from actual permitted options. Do not treat archives or invisible tasks as closed. If the delegated route is unavailable, retain local counts and finish the available briefing with a gap; no native fallback. Start one scoped batch, then prepare the briefing from local continuity while it runs. At the invocation’s cumulative wait limit, issue the briefing and receipt with pending or unverified coverage, not full sync. A late return may aid a targeted continuation for the same invocation; a separate explicit refresh needs a new observation. Do not retry blindly or create a scheduled wake.
3. Three-way compare recoverable rows. For structured/offline comparisons use `scripts/ledger_reconcile.py <request.json>`; contract describes typed inputs and output. The helper never dispatches, writes state or verifies proof. Treat results as candidates. Pull verified changes into the existing ledger via narrow, current-value-checked updates, preserve local-only notes/ownership decisions and unrelated records, and read back the exact fields. On conflicts retain both statuses; a recently fetched remote value does not itself win. Provider metadata remains a namespaced projection in existing private continuity when the ledger schema cannot store it; do not add keys to the ledger or replace local commitments. Include verified metadata in the briefing using that projection. Keep already-completed/uncertain effects separate.
4. Push only an individually authorized local status decision whose remote baseline, exact before/after, capability, effects and latest receipt still match. Stage one durable intent under the verified ClickUp route before each dispatch, with no-op/dedupe check and exact readback; do not duplicate queued, verified or uncertain writes. Bundled task-list milestone and report flows remain unchanged; do not invent status-only capability if absent. Never create/move tasks, assign owners, alter deadlines/permissions, or send notifications to reconcile a missing match. A stopped write leaves a precise blocker, and safe inbound changes or unrelated work proceed.
5. Save one compact private per-invocation receipt in existing continuity. Keep keyed baseline and latest receipt pointer with the ledger; raw provider details go in the existing private effect store and are fetched on demand only. Advance a baseline only for each field independently observed and safely reconciled, with local readback and, on outbound changes, independent exact remote readback. Preserve previous successful baselines when newer observations are partial. Add concise covered/pulled/pushed/unchanged/conflict/blocked/unmatched counts and material blockers to the briefing. No-change means complete relevant evidence, not merely no outbound mutation.
