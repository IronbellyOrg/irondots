# Shared skill routing ledger

Contract: `dot-skill-routing-ledger/1.0`. Ledger revision: **1.1.3**. This is a reusable routing template, not a record of approvals for the consuming user. Adopt only explicitly authorized routes. Public source reference (discover the actual runtime resource separately): `https://github.com/IronbellyOrg/irondots/blob/main/packages/session-init/references/skill-routing-ledger.md`.

## Interpretation and maintenance

This is the single session-routing policy module, reusable by other skills by reference. Read its current revision at every manual initialization; record identity/version/read evidence and selected rule IDs. Apply only relevant rows. A listed locator or historical verification is **not** present availability, transport access, execution, or authority. Read the actual selected skill's entrypoint before invoking its workflow; reuse a successful current-revision read within the same session. If unavailable, record the exact affected route and continue independent work; never claim it ran or silently substitute another workflow.

Higher-priority instructions and current explicit user corrections prevail. Skill-owned contracts govern implementation details; this ledger does not copy or override them, grant effects, or activate entries automatically. An unapproved proposed rule remains a proposal. Changes require authorized edits, verified names/locators, incremented ledger revision, review and actual resource readback. Preserve stable rule IDs; mark removals retired rather than silently reassigning IDs. Do not rescan all connectors or rewrite unrelated skills to update this module.

## Routing rules requiring local adoption

- **ROUTE-01 — Skill-first work.** For an action/work request, select an applicable available skill before ad hoc execution. Ordinary conversational Q&A does not require a pipeline. If a needed skill is absent, ask whether to begin specifying one; do not silently invent/build/install it.
- **ROUTE-02 — Specifications.** For an authorized request to generate or work on a spec, use `dot-spec-generator`: `https://github.com/IronbellyOrg/irondots/tree/main/packages/dot-spec-generator`. This does not authorize implementation. Its `references/adaptive-research-handoff.md` explicitly delegates material authorized investigation to the research skill with selected options; supplied-evidence drafting and localized corrections remain local.
- **ROUTE-03 — Research.** For a factual question not supported by information on hand, check official documentation first without asking. If unresolved, ask before deeper research unless that scoped investigation is already authorized. Use `adaptive-research`: `https://github.com/IronbellyOrg/irondots/tree/main/packages/adaptive-research`. Select explicit quick/normal/deep using its actual intake contract and independent complexity/importance; preserve explicit user limits. No separate imaginary research skill. Discovery/read of a module does not mean research executed.
- **ROUTE-04 — All ClickUp interactions.** Read/use the current `clickup` entry: `https://github.com/IronbellyOrg/irondots/tree/main/packages/clickup`, including its required routing/continuity resource. Recover prior progress from its private local continuity store before provider calls. ClickUp AI executes the entire authorized domain batch and creates substantive reports, including small lookups; native calls are only necessary input/transport, audience checks and independent verification/reconciliation, never a domain-work fallback. Follow the entry's separate execution contract for authorized effects; the legacy read/propose contract does not describe all AI capability. Routing grants no new authority. Browser login and connector availability are separate. Actual denial blocks that operation; preserve exact gaps, do not bypass access or change credentials, and continue independent authorized work.
- **ROUTE-05 — Final reporting.** Use ROUTE-04 and load its current reporting profile and execution contract before publication readiness; explicitly record actual profile/version acknowledgement, not compatibility inferred from legacy resources alone. The observed baseline is `clickup-ai-reporting-profile/1.2` plus `dot-brain-execution/0.1` in ClickUp's `references/brain-execution-v0.1.md`; resolve future revisions through the actual entry and reconcile unsupported versions. Also load its exact `references/reporting-protocol-v1.md`, `assets/reporting-request.md`, and `assets/reporting-result.md`: `dot-reporting/1.0`. Keep progress local; AI creates domain reports and performs authorized ClickUp publication, while one coordinator owns transport, independent verification and separately authorized faithful non-ClickUp delivery. Do not copy these contracts. Routine init creates no automatic ClickUp task/write. An already-authorized material full-briefing update in Space remains due, using the same identity and fixed finalization sequence; ClickUp no-op does not waive that persistence. Missing intended publication is pending, not no-op. Use explicitly configured project and personal-work destinations; project/privacy exceptions prevail.
- **ROUTE-06 — Named Codex skill adaptation.** For an authorized named-source compatibility/port request use `codex-to-dot-porter`: `https://github.com/IronbellyOrg/irondots/tree/main/packages/codex-to-dot-porter`. Its assessment/adaptation is not installation authorization. General specs use ROUTE-02.
- **ROUTE-07 — Session preparation.** `session-init`: `https://github.com/IronbellyOrg/irondots/tree/main/packages/session-init` is manual-first. Read this ledger and its priority-briefing module at invocation, not recursive self-invocation. Prepare the approved-scope written briefing, concise prioritized agenda and first-item context; distinguish resource readiness, functional coverage, persistence and delivery. A connection event alone is not activation; no auto-hook or deterministic timer is configured by this entry.

- **ROUTE-08 — Checkpoint synchronization.** During ongoing authorized work, recognize a material checkpoint when all necessary user inputs/decisions have been received and the work is ready/unblocked, and at meaningful milestones, blocker/decision changes and completion. Manual init also recovers and surfaces pending checkpoints; it is not the sole trigger. Route already-authorized canonical tracking through the actual ClickUp skill under ROUTE-04 and its applicable contract. For explicitly opted-in task-list progress, load its current progress/execution resources; legacy final-only consumers stay final-only. Hydrate stable work/operation/payload identities and actual receipts locally before any dispatch. Reuse the canonical record and verify pertinent live truth under that skill; do not create a second backlog. No unchanged, per-turn, keystroke or timer-driven writes, and no new background sync service. Recognizing readiness grants no effect, audience or access authority. Incomplete inputs do not mean ready; no authority, unsafe preservation, capability gap, denial or HOLD leaves an explicit pending/HOLD checkpoint with the exact gap and next permitted step. Do not use native domain fallback or unsafe append, or claim this guidance fixes a failed mirror. Preserve user edits and reconcile uncertain effects before retry; repeated init/transcripts never duplicate a send. Completion and its final delivery reuse the applicable existing operation/receipt rather than generating duplicate final publication.

- **ROUTE-09 — Requested adversarial debates.** Whenever the user explicitly asks for an adversarial debate, including a continuation or a debate within another authorized task, load and use the registered `adversarial-debate` skill before conducting it: `https://github.com/IronbellyOrg/irondots/tree/main/packages/adversarial-debate`. Discover/read the actual current entrypoint and its required resources; a locator or remembered availability is not a successful load. Follow that skill’s current workflow within the user's request and permissions, rather than improvising an equivalent-looking debate. Apply this route during the active session as well as after manual initialization. If unavailable, report the affected route/dependency gap and preserve the request; do not silently substitute a different skill or simulate a completed debate. Ordinary work, quoted mentions, discussion about debates, and initialization alone do not trigger a debate. This is instruction-level routing, not an automatic trigger, background debate, permission grant or guarantee that every future runtime loaded this ledger.

- **ROUTE-10 — All communications written as the profile owner.** Before crafting any communication as the profile owner, load and use the actual current `write-as-ryan` skill: `https://github.com/IronbellyOrg/irondots/tree/main/packages/write-as-ryan`, alongside generic writing-style and the selected channel skill. This includes initial drafts, replies, edits, delegated/voice-origin work and resumed drafts across available channels. Follow its current manifest/profile and exact-final-draft validation rather than relying on a remembered version or inherited “passed” summary. Its recipient-history protocol requires a quick search/read of the last 3–4 emails or messages **sent by the profile owner to that specific verified person**, recording recipient nuances and unavailable/limited history alongside the general profile; incoming text is context, not profile-owner style evidence. Delegate the actual constraints and readable private evidence, require the receiving writer to review them and reread the guide, and revalidate after edits. Preserve ClickUp AI-first ownership and all recipient, privacy, authority and channel gates. Dot's own replies, ordinary AI reports and quoted text are not communications written as the profile owner. Apply this routing during ongoing work as well as after initialization; init alone does not trigger correspondence searches, drafting, publication or new disclosure. If the guide is unavailable, follow its explicit provisional/hold/exception rules or record the blocked dependency, never claim it loaded. This is instruction-level routing, not universal automatic invocation or a transport interceptor.

The public `write-as-ryan` export supplies only generic guidance and synthetic examples. ROUTE-10 requires a separately configured, authorized private profile; the synthetic example cannot establish production readiness.

## Dependency behavior

Load only the selected skill and its required resources at the actual task boundary, not every package during init. Include applicable rule IDs and unresolved dependencies in the prepared core/receipt. Missing ledger blocks truthful initialization; a missing downstream skill blocks only its dependent action. If a current source contract conflicts with a ledger rule, preserve the conflict and pause the affected effect; do not turn a stored rule into additional permission.
