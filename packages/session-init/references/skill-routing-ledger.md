Contract: `dot-skill-routing-ledger/1.0`. Ledger revision: **1.0.1**. Verified entrypoint reads: **2026-11-02 UTC**. Owner: approved user routing, maintained through authorized skill updates. Public source reference (discover the native resource by skill name): `https://github.com/IronbellyOrg/irondots/blob/main/packages/session-init/references/skill-routing-ledger.md`.

## Interpretation and maintenance

This is the single session-routing policy module, reusable by other skills by reference. Read its current revision at every manual initialization; record identity/version/read evidence and selected rule IDs. Apply only relevant rows. A listed locator or historical verification is **not** present availability, transport access, execution, or authority. Read the actual selected skill's entrypoint before invoking its workflow; reuse a successful current-revision read within the same session. If unavailable, record the exact affected route and continue independent work; never claim it ran or silently substitute another workflow.

Higher-priority instructions and current explicit user corrections prevail. Skill-owned contracts govern implementation details; this ledger does not copy or override them, grant effects, or activate entries automatically. An unapproved proposed rule remains a proposal. Changes require authorized edits, verified names/locators, incremented ledger revision, review and actual resource readback. Preserve stable rule IDs; mark removals retired rather than silently reassigning IDs. Do not rescan all connectors or rewrite unrelated skills to update this module.

## Approved routing rules

- **ROUTE-01 — Skill-first work.** For an action/work request, select an applicable available skill before ad hoc execution. Ordinary conversational Q&A does not require a pipeline. If a needed skill is absent, ask whether to begin specifying one; do not silently invent/build/install it.
- **ROUTE-02 — Specifications.** For an authorized request to generate or work on a spec, use `dot-spec-generator`: `https://github.com/IronbellyOrg/irondots/blob/main/packages/dot-spec-generator/SKILL.md`. This does not authorize implementation. Its `references/adaptive-research-handoff.md` explicitly delegates material authorized investigation to the research skill with selected options; supplied-evidence drafting and localized corrections remain local.
- **ROUTE-03 — Research.** For a factual question not supported by information on hand, check official documentation first without asking. If unresolved, ask before deeper research unless that scoped investigation is already authorized. Use `adaptive-research`: `https://github.com/IronbellyOrg/irondots/blob/main/packages/adaptive-research/SKILL.md`. Select explicit quick/normal/deep using its actual intake contract and independent complexity/importance; preserve explicit user limits. No separate imaginary research skill. Discovery/read of a module does not mean research executed.
- **ROUTE-04 — All ClickUp interactions.** Read/use the current `clickup` entry: `https://github.com/IronbellyOrg/irondots/blob/main/packages/clickup/SKILL.md`, including its required routing/continuity resource. Recover prior progress from its private local continuity store before provider calls. ClickUp AI executes the entire authorized domain batch and creates substantive reports, including small lookups; native calls are only necessary input/transport, audience checks and independent verification/reconciliation, never a domain-work fallback. Follow the entry's separate execution contract for authorized effects; the legacy read/propose contract does not describe all AI capability. Routing grants no new authority. Browser login and connector availability are separate. Actual denial blocks that operation; preserve exact gaps, do not bypass access or change credentials, and continue independent authorized work.
- **ROUTE-05 — Final reporting.** Use ROUTE-04 and load its current reporting profile and execution contract before publication readiness; explicitly record actual profile/version acknowledgement, not compatibility inferred from legacy resources alone. The observed baseline is `clickup-ai-reporting-profile/1.2` plus `dot-brain-execution/0.1` in ClickUp's `references/brain-execution-v0.1.md`; resolve future revisions through the actual entry and reconcile unsupported versions. Also load its exact `references/reporting-protocol-v1.md`, `assets/reporting-request.md`, and `assets/reporting-result.md`: `dot-reporting/1.0`. Keep progress local; AI creates domain reports and performs authorized ClickUp publication, while one coordinator owns transport, independent verification and separately authorized faithful non-ClickUp delivery. Do not copy these contracts. Routine init returns a minimal receipt in-session, a justified no-op with no ClickUp task/write. Missing intended publication is pending, not no-op. IronFlow is default for AI/automation, CEO for other personal work, explicit project/privacy exceptions prevail.
- **ROUTE-06 — Named Codex skill adaptation.** For an authorized named-source compatibility/port request use `codex-to-dot-porter`: `https://github.com/IronbellyOrg/irondots/blob/main/packages/codex-to-dot-porter/SKILL.md`. Its assessment/adaptation is not installation authorization. General specs use ROUTE-02.
- **ROUTE-07 — Session preparation.** `session-init`: `https://github.com/IronbellyOrg/irondots/blob/main/packages/session-init/SKILL.md` is manual-first. Read this ledger at invocation, not recursive self-invocation. A connection event alone is not activation; no auto-hook or deterministic timer is configured by this entry.

## Dependency behavior

Load only the selected skill and its required resources at the actual task boundary, not every package during init. Include applicable rule IDs and unresolved dependencies in the prepared core/receipt. Missing ledger blocks truthful initialization; a missing downstream skill blocks only its dependent action. If a current source contract conflicts with a ledger rule, preserve the conflict and pause the affected effect; do not turn a stored rule into additional permission.
