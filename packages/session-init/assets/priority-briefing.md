# Working briefing shape

Use only supported facts, explicit unknowns and the existing report's structure; this is a checklist, not permission to replace human formatting. Do not create a second ledger merely to use this shape.

- Briefing identity/version; generated_at; last successful refresh.
- Coverage: approved scope, sources read/reused, source update/as-of times, fetched_at, missing/partial/stale areas and exact limitations.
- Recommended order: short reason for each user-attention item, impact/unblocking, urgency, waiting age when known, and whether it can finish now.
- By initiative: canonical item/source link, owner, status/progress, exact user decision/action or none, dependencies/blocker, waiting-on, evidence dates and next permitted step.
- Unanswered GitHub mentions/assigned questions when in approved scope, with thread evidence and response status.
- Delegated/in-progress and waiting/deferred items, distinguishing actual recent worker evidence from unknown activity.
- Newly closed/user-confirmed outcomes and any provider reconciliation gap, without reopening them unnecessarily.
- First-item context: background/prior decision, evidence, options/trade-offs if relevant, one next question.
- Persistence outcome: same report identity/version and actual write/no-change receipt, or last-good version and exact pending gap.

Spoken opening: concise priority overview, then the first item and one question. The complete report is not capped by the compact core's 500-word limit.
