# Preparation and validation

## Preparation

Record the actual current request, intended meaning, literal strings, exclusions,
verified recipient/audience, account/channel/thread, purpose, relevant relationship
evidence, profile version/hash and real reads. Keep context task-local. Recipient
resolution is independent of tone selection; matching names or titles do not
establish identity. Include the [recipient-history](recipient-history.md) check's
actual eligible message counts/dates, evidence, supported nuances and gaps.

## Hard gates and style review

All seven hard gates must pass for sending: identity, channel, authorization,
meaning, privacy, exact_strings and current_context. Unknown is not pass. Saving
a native draft and sending have separate permissions. Evaluation grants neither.

Review all ten style dimensions: opening_closing, directness, request_framing,
rhythm, length, structure, vocabulary_contractions, warmth_humor, punctuation,
recipient_context_fit. Each needs a reason and status matches,
acceptable-with-limitation or mismatch. Record limitations for limited dimensions;
do not average away material mismatch. Do not add feelings or manufacture
familiarity. Literal requested text overrides inferred style where applicable.
Use only applicable rules from an authorized private profile. The public fixture
is not a style model, user correction, permission record or personal preference.

## Holds, repair and exact bytes

Missing/corrupt/unverified profile or material unresolved style mismatch holds
send. A healthy profile with honestly limited evidence may support restrained
private drafting, with material limits disclosed. An informed exact-draft style
exception needs disclosed limitation and explicit user agreement, not generic
send approval. It never waives hard gates or grants authority. This skill sends
nothing. A useful draft-only result is not a failed writing task merely because
it is ineligible for sending.

Hash UTF-8 exact final bytes without normalization. Verify facts and real evidence
independently. The checker validates declared structure, consistency and digest,
not actual reads, recipient resolution, authorship, meaning or user intent.
Changes in text, including punctuation or a signature, invalidate old validation.
An unchanged approved draft need not be rewritten merely because the profile
version changed, but retained basis requires current-guide health, the exact old
artifact and prior receipt/draft/profile identity plus latest-context review.

## Declaration integrity

Use real booleans, complete gates and dimensions, exact supported channel values,
nonempty scope and actual loaded rule IDs. Profile, context, manifest and receipt
JSON are parsed strictly; duplicates/nonfinite values and digest disagreement fail.
Type-valid evidence is not necessarily true. No unavailable script/read means
validation may be skipped. Follow the [workflow/manual protocol](workflow-safeguards.md).

The checker is specifically a send-gate checker. `mode: draft-only` and
`send_eligible: false` correctly hold. Do not falsely declare send-authorized to
obtain green output for a private draft. Store meaningful draft-quality findings
separately. The synthetic test's send-authorized declaration is explicitly
fictional and must never be reused for a real task.

Bind the actual input with `--input`. Without it, the standalone checker can
report input_binding_verified false even when other declarations are consistent.
The workflow gate always binds actual task bytes. A live receipt uses the exact
request, not made-up test bytes. Keep full receipts, source references and hashes
private and proportionate. Script success proves neither style quality nor consent.
