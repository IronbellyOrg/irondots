# Channel adapters and coverage

Every route uses current-guide reads, preparation, exact-final validation and
then the channel's existing permission checks. The [history check](recipient-history.md) and [workflow safeguards](workflow-safeguards.md)
apply to direct/reply/delegated/voice-origin/resumed work. Named invocation or
verified runtime routing is needed; this source does not patch managed entrypoints
or intercept sends. Public metadata defaults to explicit invocation because a
separately authorized private profile must be configured first.

- Email: read installed `orbit:email` and `orbit:writing-style`; verify account,
  to/cc/bcc, reply thread, attachments and separate draft/send authority.
- Slack: read installed `orbit:slack` and writing-style; verify workspace,
  channel/DM/thread and people. Group audience differs from a private DM.
- ClickUp: read actual `clickup` and writing-style resources, personalized-writing
  adapter and current reporting contracts. Preserve its authorized AI batch
  executor and local staging contracts. Private validation does not replace
  domain execution, authorize native substitution after a failed AI route, or
  permit disclosure of profiles and samples. Any downstream newly composed text
  needs supported pre-publication staging and exact validation before publication.
- Text: read the relevant channel skill. A dot-to-user transport is not evidence
  of a route for user-authored messages to other people. Prepare privately when
  requested; use only a separately verified authorized account/destination/transport
  for a third-party effect.
- Documents: apply only to explicit user-authored writing, in the format requested
  by the user and supported by the destination. Ordinary assistant reports are
  not converted to personal authorship by this template.
- Delegated, voice-origin and resumed work: convey actual authority and scoped
  facts. The writer performs its own real profile/context reads and validation.
  Reconcile uncertain effects before retry.

For substantial authorized profile/skill work, use the installed ClickUp reporting
protocol only when applicable and authorized; parent is sole delegated publisher.
Ordinary private drafting has no reporting side effect. Never place correspondence
samples in a shared task or repository to demonstrate this integration.

Offline fixtures prove only their local consistency checks. Saving a package,
registered discovery/readback, helper execution, explicit-route testing and live
provider behavior are separate outcomes. A missing registered reader is a blocked
read test, not a successful installation or reason to silently substitute a local
copy. Do not send external evaluation messages. Report actual coverage and gaps
without asserting global routing or authentic voice improvement.
